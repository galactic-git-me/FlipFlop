The one decision this whole plan hinges on

Your spec assumes a single lineage: Component → Build → Product → Order. The codebase actually has four separate "build" concepts that never fully connect:

Flip — purchased listing, resold. Has its own stage machine + eBay fields. Self-contained. PCBuild — configurator JSON build. Feeds the orchestration bridge below. ManualBuild — today's new feature. An island: no inventory link, no Build-bridge link, no Order link. Build — orchestration bridge. build_type: FLIP | MADE_TO_ORDER | PREBUILT. FKs: flip_id, pcbuild_id, order_id · NO manual_build_id. Order — customer checkout. FKs to playbook_id / theme_id — NOT to Build at all.

So even the parts that are individually well-built (Order lifecycle, Stripe checkout, inventory allocation) don't hang off the same spine. Before touching states, procurement, or artifacts, this needs a call: extend the Build bridge to cover ManualBuild and wire Order → Build (lowest-risk, follows the precedent PCBuild already set) — or something else. Everything below assumes that decision is still open.
