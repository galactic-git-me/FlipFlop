Subsystem 1: Catalogue Layer

Changes to FlipFlop that power the customer website. Everything the site shows comes from here.

What this subsystem does

Component Slots

Playbook → Parts

Each playbook defines which component slots it has (CPU, GPU, RAM, Storage) and which inventory items are available as variants in each slot. Admin curates which super-gems "go live".

Case Catalogue

The Hero Product

A managed list of cases (Lian Li, Fractal, NZXT, etc.) with manufacturer images. Admin adds cases manually. Cases are not scraped — they're curated.

Freshness Engine

2-Run Rule

Component variants auto-hide if not seen in 2 consecutive hourly scrape runs. Reappear if seen again within 24h. Never more than 2 hours stale.

Pricing Layer

Live + Buffer

Prices update every hourly run. A 15% buffer margin is baked in at publish time. Display price = latest scrape price × 1.15 (rounded up to nearest £5).

Data flow

Hourly scrape → Listings table
    ↓ gem detection
Super gems → Admin reviews → "Publish to site" toggle
    ↓ assigned to playbook slot
Component variants → exposed via /api/catalogue
    ↓ freshness check every run
Customer site reads catalogue → shows live options
