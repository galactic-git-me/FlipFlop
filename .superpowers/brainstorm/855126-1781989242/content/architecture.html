Catalogue Layer — Architecture

How the pieces connect. FlipFlop grows three new concepts: Slots, Variants, and Cases.

Data model

EXISTING
Playbook (id, name, status, keywords…)
Listing (id, title, price, gem_score, component_type…)

NEW
playbook_slots
  playbook_id → Playbook
  slot_type: cpu | gpu | ram | storage | cooling | os
  is_customer_visible: bool
  tier_names: json → {"budget":"Starter","mid":"Battle-Ready","high":"Beast Mode"}
  score_band_budget: [40, 65]  score_band_mid: [65, 80]  score_band_high: [80, 100]

catalogue_variants
  listing_id → Listing
  slot_id → playbook_slots
  status: pending_review | active | hidden | rejected
  display_price: float → scrape_price × 1.15, rounded to £5
  consecutive_misses: int → auto-hide at 2
  last_seen_at: datetime
  auto_published_at: datetime

case_catalogue
  name, brand, form_factor: atx | matx | itx
  images: json → [manufacturer photos]
  rrp_gbp: float
  is_transparent_panel: bool
  status: active | hidden
  component_image_slots: json → where GPU/CPU cooler appear through glass

Hourly scrape run additions

Auto-publish step

After gem detection: any gem with score ≥ threshold AND matching a defined slot → create catalogue_variant with status=pending_review. Runs silently in background.

Freshness step

For every active variant: if listing not seen this run → consecutive_misses++. At 2 → status=hidden. If seen again within 24h → status=active, misses reset to 0.

Price update step

For every active variant: recalculate display_price from current listing price × 1.15, round up to nearest £5. No admin action needed.

Review digest

Once daily (morning): count pending_review variants → if > 0, emit alert to admin. Admin reviews in FlipFlop, approves or rejects. Approved → status=active.

New API endpoints

# Admin (FlipFlop)
GET  /api/catalogue/review-queue     → pending_review variants for admin
POST /api/catalogue/variants/{id}/approve
POST /api/catalogue/variants/{id}/reject
GET  /api/catalogue/cases            → admin list
POST /api/catalogue/cases            → add a case
PATCH /api/catalogue/cases/{id}

# Public (customer site)
GET  /api/public/playbooks          → active playbooks + tier names
GET  /api/public/playbooks/{id}/slots  → slots + variants grouped by tier
GET  /api/public/cases              → active cases for configurator
