# Product identity standards and lookup services for FlipFlop

Researched 26 October 2026 using official standards, platform documentation, provider documentation and manufacturer material. No accounts were created, subscriptions purchased or authenticated APIs tested. Provider coverage of FlipFlop's ninety-product sample remains unmeasured.

## Recommended direction

Use an internal immutable product-variant ID and attach independently evidenced external identifiers to it. Resolve an incoming offer using a hierarchy of validated GTIN, manufacturer+MPN, already verified source-specific identifiers, and complete category-specific attributes. Use fuzzy titles or an LLM to find candidates and extract missing fields; do not derive canonical product identity from whichever free-form name the model supplies.

This is a recommendation for FlipFlop, inferred from the practices below. It is not a claim that an external database can supply all the retailer offers or automatically resolve every ambiguous hardware title.

## Identifier hierarchy

1. **Validated GTIN at the correct trade-item/packaging level.** Accept GTIN-8/12/13/14 as digit strings, validate the GS1 check digit, retain the original value and compare a zero-padded fourteen-digit representation. UPC-A `740617344790` and EAN-13 `0740617344790` consequently refer to the same number; neither should become an integer. A valid checksum only proves structure, not that a seller assigned the number to the right product. GS1 registry verification and source agreement remain separate evidence. [GS1 uniqueness/zero-padding](https://support.gs1.org/support/solutions/articles/43000734386-are-all-gtins-unique-numbers-), [check digits](https://www.gs1.dk/en/resources/tools), [GS1 verification](https://support.gs1.org/support/solutions/articles/43000734070-how-do-i-check-if-a-gs1-gtin-is-valid-).
2. **Canonical manufacturer/brand plus exact manufacturer part number.** Normalize presentation and approved brand aliases, preserve raw values, and do not strip variant-bearing suffixes or punctuation indiscriminately. A retailer SKU is not automatically a manufacturer MPN. Google documents MPN as manufacturer-specific; Icecat requires brand alongside its product code. [Google product specification](https://support.google.com/merchants/answer/14779112?hl=en), [Icecat identifier guide](https://iceclog.com/manual-how-to-import-product-content-into-your-webshop-via-icecat/).
3. **Previously verified source-local aliases.** Reuse a validated child ASIN, ePID, or vendor listing ID when it still describes the same variant. Preserve the source namespace and evidence. A parent ASIN or a merchant's category/search-page ID must not stand in for a purchasable product variant.
4. **Exact structured variant signature.** Where IDs are genuinely absent, require the relevant manufacturer, series/model and value-defining variant fields. Examples: RAM DDR generation, total kit capacity, module count, speed and timings; SSD family/capacity/form factor/heatsink variant; GPU board manufacturer/model/VRAM. These particular signatures are FlipFlop engineering recommendations, not a single universal external hardware standard.
5. **Title similarity, images and LLM extraction.** Use these to retrieve candidate products or propose structured fields, then apply deterministic contradiction checks. Missing fields are unknown. An explicit DDR4/DDR5, 2230/2280, LPX/RGB or 2×16/4×8 conflict must block automatic equivalence. Never let weak transitive matches combine two strong identities.

GTINs identify trade items and packaging levels, so a retail RAM kit, individual module and multipack must remain distinguishable. GS1's management standard explicitly treats pack quantity and predefined assortment as identity changes. [GS1 GTIN Management](https://www.gs1.org/1/gtinrules/en/).

### Icecat licence and empirical access limits

Icecat's published Content License has material restrictions: section3.a addresses ownership of AI-derived model parameters, vector embeddings and other model artifacts and prohibits deploying/transferring/selling the described artifacts; sections2.b/3.a address content reuse and third-party manufacturer rights. This is a concrete reason to verify the applicable Open/account agreement before using its content in embeddings or model training. Free account access does not establish unrestricted redistribution or image/3D-generation rights. Structured lookup/enrichment should be assessed under the actual account terms. [Published Content License](https://iceclog.com/content-license-icecat/).

No public search in this research established exact Open Icecat coverage for Kingston `SNV3S/1000G`, and no authenticated API response was obtained. The correct next experiment is an authorized registered lookup, not a claim of coverage from Icecat's overall catalogue size. The manufacturer itself provides a direct exact-part lookup returning the NV3 M.2 2280 product. [Kingston exact-part lookup](https://www.kingston.com/en/memory/search?partid=SNV3S%2F1000G).

## Concrete Kingston example

Kingston's own datasheet distinguishes `SNV3S/1000G` (M.2 2280) from `SNV3SM3/1T0` (M.2 2230), although both are marketed as NV3 1TB. [Kingston datasheet](https://www.kingston.com/datasheets/SNV3S_en.pdf).

The UK distributor CPC explicitly lists manufacturer part number `SNV3S/1000G` and GTIN `0740617344790` on the same product page. This is direct first-party retailer evidence for the mapping; it has not been independently queried against the GS1 registry in this research. [CPC product page](https://cpc.farnell.com/kingston/snv3s-1000g/ssd-nv3-m-2-2280-pcie4-0-nvme/dp/CS37702).

Therefore a vendor offer headed “Kingston NV3 NVMe1TB”, one headed “1TB Kingston NV3 PCIe4.0 SSD”, and the Amazon title can share an internal product variant when they expose that same validated MPN/GTIN. A 2230 `SNV3SM3/1T0` offer must remain a separate variant regardless of title similarity. Current stock, condition, VAT and delivery belong to each offer, not to the product identity.

## Low-cost adoption sequence

1. Repair extraction and the local identifier registry first. Collect GTIN, brand and MPN from known product pages and retain raw values/evidence. This addresses data already available without an API subscription.
2. Run a coverage experiment with the existing ninety products: known identifier in, exact variant out, recording covered/ambiguous/missing/conflicting results. Pilot Open Icecat first.
3. Use manufacturer evidence and a limited GS1 verification path for conflicts. Ask GS1 UK about API entitlement only if the conflict volume warrants it.
4. Test an EAN-Search or Barcode Lookup account only if the remaining identifier gaps justify its incremental cost and permitted usage. Cache validated identity facts under the provider's terms; refresh retailer prices and stock separately.
5. Keep missing/ambiguous products visible as pending candidates and target exact-MPN discovery. Measure both missed true links and false merges; vendor-count growth alone is not a correctness metric.
