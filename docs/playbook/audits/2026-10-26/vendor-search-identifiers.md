## Detail-page findings added

The new final column records product-detail identifiers, separately from search results. Structured evidence and exact locations are in `vendor-search-identifiers.json` under each vendor's `product_detail` key. Amazon's detail example is the 1TB product to align the comparison; its original search example was 500GB. The 500GB detail was also inspected and has UPC `740617344806`.

**Confirmed cross-vendor barcode bridge:** Amazon, Scan, AWD, Computer Orbit and Newegg expose `740617344790`; Overclockers and Ebuyer expose `0740617344790`. Both normalize to GTIN-14 `00740617344790`. All seven refer to the sampled Kingston NV3 1TB product, manufacturer part `SNV3S/1000G`. Length/checksum and leading-zero equivalence were checked offline; no GS1 ownership service was called.

**Field labels cannot be trusted blindly:** Overclockers' JSON-LD `mpn` repeats its internal `STO-KNG-02942` SKU. Computer Orbit's JSON-LD `mpn` contains the barcode `740617344790`, while its SKU is the actual manufacturer part code. AWD labels a GTIN-12 value as EAN. Gamers Outlet declares a checksum-valid GTIN, but its ownership and exact licence mapping remain unverified; its `mpn` is the generic text `Windows 11 Pro`.

Google is an aggregator: the inspected result links directly to Scan, whose detail page was audited. No separate Google-owned product-detail identifier was verified.

## Meaning of the identifiers

- GTIN/EAN/UPC is a global trade-item key when valid and assigned to the exact variant/package. None was explicitly exposed in the sampled results fields inspected. The detail-page column now demonstrates the additional barcode coverage.
- Manufacturer plus exact MPN is the practical cross-vendor key already visible on many results pages. Kingston confirms `SNV3S/1000G` and `SNV3SM3/1T0` are different part numbers/form factors. [Manufacturer datasheet](https://www.kingston.com/datasheets/SNV3S_en.pdf).
- ASIN links Amazon catalogue records; eBay listing IDs identify eBay offers. Neither is a universal hardware ID.
- SKU is a merchant-specific property. Computer Orbit happens to populate its SKU with an actual Kingston MPN in this sample; AWD and Ebuyer use unrelated internal codes. The field name alone does not establish cross-vendor identity. [Schema.org SKU](https://schema.org/sku), [MPN specification](https://support.google.com/merchants/answer/6324482?hl=en).
- Google public `data-offer-id` was observed as a DOM field. Its general semantics are not inferred from Merchant API docs. The Ebuyer numerical overlap is a concrete merchant-scoped observation, not a universal guarantee.

## Immediate implications for FlipFlop

1. Keep vendor ID, product ID, variant ID and exact URL as source-record aliases. Keep tracking UUID/index separately from identity.
2. Capture inline product/variant JSON as well as JSON-LD and HTML attributes. Computer Orbit is a concrete missed opportunity for the current JSON-LD/card-only identifier enrichment.
3. Extract manufacturer codes from the exact result card title/image title when present; manufacturer-scope them and retain suffixes. Avoid concatenated whole-page text, which can append accessibility text such as `Opens` or `About` to an apparent MPN.
4. For Scan and Ebuyer samples, use one cached exact product-detail enrichment to find MPN/GTIN; model/capacity text alone is not a proven exact variant.
5. Treat software titles/slugs as offer descriptors, not evidence of a universal licence product identifier or licence rights.

## Reproducibility and limits

`vendor-search-identifiers.json` records public example values and selectors. `vendor-html/manifest.json` records direct HTTP outcomes; four successful response HTML files underpin the static inspections. Browser-only fields are recorded as minimal public snippets in the JSON report rather than exporting signed-in HTML. `vendor-identifier-standards.md` provides separately researched primary-source definitions.

Bargain Hardware redirected the memory search to its RAM category; that listing page was inspected and is explicitly identified above. Ebuyer and Google grids required their rendered results, so an initial document read would incorrectly have suggested no usable IDs.
